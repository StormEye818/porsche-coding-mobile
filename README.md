# Porsche Coder

**保时捷 981 隐藏功能编码工具**（iOS）· 仅适配 **vLinker MS** 诊断适配器

给车友用的 DIY 工具。目前是**只读**状态——能读出车上编码、按 byte/bit 位置显示、做备份，
但**写入功能受结构性闸门保护**（见下方「安全说明」）。

### 写入安全说明

写入功能**已实现**，受**结构性闸门**保护：

1. **SID 配对检查**：读写服务必须配对（`21↔3B` / `22↔2E` / `1A↔3B`），只读项拒绝写入
2. **LID 必须存在**：缺 LID 的参数不给写
3. **变更范围检查**：写入值不能超出 bitsize 范围
4. **回读校验**：写入后回读比对，不一致报错

**seed/key 口令算法已实现并通过 完整性验证**（双算法各 74/74 测试向量一致）。

⚠️ **风险提醒**：改错编码可能导致功能异常、故障灯、甚至需要 4S 恢复。建议先在**模拟模式**体验流程。

### 免责声明

- 刷编码有风险。改错了可能导致功能异常、故障灯、甚至需要 4S 恢复。
- 本工具不提供任何担保。使用风险自负。
- **每次只改一项**，改前先备份，改后核对回读。

## 部署步骤（Xcode）

### 1. 解压并打开工程

解压后进入 `ios/` 目录，双击 `App/App.xcodeproj` 用 Xcode 打开。

### 2. 解决依赖

Xcode 打开后会自动拉取 SPM 依赖（Capacitor）。等右上角转圈结束。
如果报错：**File → Packages → Resolve Package Versions**

### 3. 设置签名

左侧点 **App** 项目 → **TARGETS: App** → **Signing & Capabilities**：

- **Team**：选你的 Apple ID（没有就点 Add an Account）
- **Bundle Identifier**：改成你自己的，例如 `com.你的名字.porschecoder`
  （默认 `cn.bigmiao.porschecoder` 可能和别人冲突）

### 4. 连手机，选设备

iPhone 用 USB 连 Mac → 顶部设备选择器选你的 iPhone。
第一次会提示「信任此电脑」→ 手机上点信任。

### 5. 运行

点左上角 **▶ Run**（或 `Cmd+R`）。

首次运行手机上要去：**设置 → 通用 → VPN与设备管理** → 信任你的开发者证书。

### 6. 免费账号的限制

免费 Apple ID 签名 **7 天过期**，过期后 app 打不开，重新 `Cmd+R` 装一次即可。
付费开发者账号（$99/年）可以一年不用管。

### 阶段二：第一次上车（熟悉流程，约 20 分钟）

#### 步骤 1：插适配器

1. 找到 OBD 口（981 在**驾驶员侧仪表台下方，转向柱左下**）
2. **vLinker MS 插入 OBD 口**
3. 看适配器指示灯是否亮起（没亮说明没电，检查是否插紧）
4. **点火 ON** —— 注意是 ON 不是 ACC
   - 判据：仪表盘所有灯亮起、屏幕点亮
   - **不用发动发动机**（但电压偏低时建议发动一下充电）

#### 步骤 2：手机连蓝牙（最容易卡住的一步）

**这步必须在 iOS「设置」里做，App 替代不了。**

1. 打开 **设置 → 蓝牙**
2. 在「我的设备」或「其他设备」里找 **vLinker MS**
3. **必须显示「已连接」三个字**
   - 显示「未连接」→ 点一下它
   - 一直转圈 → 拔插 vLinker 重来
   - 找不到 → 确认适配器指示灯亮、点火 ON

> **判据**：设置里显示「已连接」，这一步才算完成。
> 没连上就打开 App，一定扫不到设备。

#### 步骤 3：打开 App 做自检

1. 打开 **Porsche Coder**
2. 点 **开始自检**
3. 等 L1–L5 逐层跑完（约 10–20 秒）

**看结果**：

| 结果 | 说明 | 下一步 |
|---|---|---|
| 5 层全 ✅ | 链路完全通 | 继续步骤 4 |
| L1 ❌ | 手机蓝牙没连上 | 回步骤 2 |
| L2 ❌ | EA 会话开失败 | 拔插 vLinker，回步骤 2 |
| L3 ❌ | 适配器没响应 | 点火 ON？被别的 App 占用？ |
| L4 ❌ | 协议没锁定 | 看提示，多半是电压/点火 |
| L5 ❌ | 模块没应答 | 可能是网关路由，发日志给我 |

**失败了不要反复点** —— 会形成僵尸会话。按提示的修复方法做。

#### 步骤 4：读 ECU 身份

点 **读 ECU 身份** → 显示：

```
DSN       P200
软件版本   W06C30C1348CD1L
硬件版本   H04
```

**这三个值能确认你的车匹配到正确的参数表。**

#### 步骤 5：读当前编码

点 **读当前值** → 会列出每个参数：

```
巡航                    byte 0 · bit 0 · 宽 1     当前值：否
  [仅源定义（未实车验证）] [风险 中]

启停 Start/Stop          byte 0 · bit 3 · 宽 1     当前值：是
  [仅源定义（未实车验证）] [风险 低]
```

**每个参数显示 5 样东西**：
1. **功能名**
2. **byte / bit 位置** —— 在编码块哪个字节哪一位
3. **当前值** —— 解码后的人话
4. **验证等级** —— 决定能不能写
5. **风险等级** —— low/medium/high

#### 步骤 6：备份（重要！）

点 **备份当前编码** → 存到本地。
**以后要恢复原状就靠这个。**

#### 步骤 7：导出记录

点 **分享** → 选 **AirDrop** 发到电脑，或发微信/备忘录。
这个记录包括完整的 AT 命令和应答，**发给能帮你分析的人**。

### 阶段三：读懂结果

#### 「byte 0 · bit 0」是什么意思

车上每个模块有一块**编码区**（一串字节）。每个功能占其中几位：

```
byte 0 =  0 0 1 0 1 0 0 0
          │ │ │ │ │ │ │ └─ bit 0 = 巡航
          │ │ │ │ │ │ └─── bit 1 = ACC
          │ │ │ │ │ └───── bit 2 = 变速箱类型
          │ │ │ │ └─────── bit 3 = 启停
          │ │ │ └───────── bit 4 = (未知)
          │ │ └─────────── bit 5 = 排气阀
          │ └───────────── bit 6 = (未知)
          └─────────────── bit 7 = (未知)
```

**改某个功能 = 改对应的那一位。** 这就是为什么需要对照表。

#### 「验证等级」是什么

| 等级 | 含义 | 能写吗 |
|---|---|---|
| `source-defined` | 只有静态源定义 | ✅ 可写（结构性闸门保护） |
| `read-confirmed` | 实车读回验证过 | ✅ 可写 |
| `write-confirmed` | 实车写入 + 回读验证过 | ✅ 可写 |

**`level` 是验证状态标注**，不作为写入门禁。真正保护写入的是结构性闸门（SID 配对 / LID / 范围 / 回读）。

#### 「风险等级」是什么

| 风险 | 典型 | 建议 |
|---|---|---|
| **低** | 灯光、菜单显示、舒适功能 | 相对安全 |
| **中** | 车速阈值、记忆功能 | 想清楚再动 |
| **高** | 变速箱、ACC、安全气囊、制动 | **不要碰** |

## 连接自检说明

自检分 5 层，逐层验证：

| 层 | 验证什么 | 失败意味着 |
|---|---|---|
| **L1** | EA 配件可见 | 手机蓝牙设置里 vLinker 不是「已连接」 |
| **L2** | EA 会话打开 | 链路被占用或僵尸会话，需拔插重连 |
| **L3** | ELM327 活着 | 适配器没上电，或被别的 App 占用 |
| **L4** | 协议锁定 | 点火/电压问题，或波特率不对 |
| **L5** | 模块可达 | 该模块在网关后面的总线上，或地址需调整 |

**L4 的两种失败要区分**：
- `NO DATA` = 协议层通了但没 ECU 应答 → 查点火、电压、发动机是否真启动
- `CAN ERROR` = 波特率不对 → 981 应为 `ATSP6`（11bit/500k）

## 技术细节（给想了解的人）

### 适配器通信

vLinker MS 是 **MFi 蓝牙串口设备**，不是普通 BLE。
iOS 通过 **External Accessory** 框架访问，系统持有蓝牙链路。

### 保时捷诊断协议

- 总线：**CAN 11bit / 500k**（`ATSP6`）
- 服务：**KWP-2000 风格**（`1A 9F` 读 DSN 等），不是标准 UDS `22`
- 会话：`10 89`（保时捷专用，不是标准 `10 03`）
- 网关：`710/77A`（注意 **rx ≠ tx+8**）
- DME：`7E0/7E8`

### 编码结构

每个参数在编码块里占若干位：

```
byte N 的 bit M，宽度 W
枚举值 ↔ 含义（TEXTTABLE）
```

例如 DME EU5 的 `byte 0`：

| bit | 功能 |
|---|---|
| 0 | 巡航 |
| 1 | ACC |
| 2 | 变速箱类型 |
| 3 | 启停 |
| 5 | 排气阀 |

## 常见问题

**Q: 为什么我的 vLinker 在 App 里扫不到？**
A: 去 **设置 → 蓝牙** 确认显示「已连接」。MFi 设备由 iOS 系统持链路，
App 只能在系统已连接的前提下看到它。

**Q: 自检卡在 L4，全 NO DATA？**
A: 检查点火是否 ON（不是 ACC）、电压 >12.4V、发动机是否真启动了。

**Q: 写入功能安全吗？**
A: 写入受结构性闸门保护（SID 配对/LID/范围/回读）。口令算法已验证。
但**改编码本身有风险**——建议先模拟模式体验，上车时每次只改一项、改前备份。

**Q: 我想加新的编码功能怎么办？**
A: 25 车型的编码数据已全覆盖，共 110 万条。
数据文件在 `data/models/` 目录下，按车型/模块组织。
