# 全量修复 + 后续审计 QA 改进规划（2026-11-20）

## 0. 本轮结论

当前 v0.8.0 的「243/243 全 A、QA 15/15、10+1 注入」证明的是：**E0 账本、生成器、审计快照和合成/分类向量各自自洽**。它没有证明：**真实生产数据被运行时正确消费，且模拟/真车边界没有串线**。

实车与模拟两份日志共同暴露的 P0 断接：

- T02 生成器写 `cands / pairs / truth / requestKeys`；
- T03 `src/sweep.js:69-73`、`src/app.js:636` 仍读 `can / requestKey` 单数；
- 真实 `bind-plan.json` 中 623 条只有 `0x0f4d` 因四元特例含顶层 `can/requestKey`，其余 622 条 `selectAddrRows()` 为 0；
- 于是 `0x0e23` 的真实 `0x070D/0x0777 + requestKeys` 读不到，fallback 到 `ecu-addresses.json` tabB1 共享候选，并被置 `requestKey:null`，触发 `app.js:710` fail-closed；
- 测试用 `tools/test-align431.mjs:139-160` 的合成 fixture 恰好使用 `can/requestKey` 单数形状，因此 47/0 全绿，却没有覆盖生产形状。

因此：这不是 431 E0 做法错，而是**我方生成器/消费者契约漂移 + 门禁 fixture 假绿 + 模拟模式范围误用**。

## 1. 审计发现全集

### P0-1 生产 schema → runtime 断接

- 位置：`tools/export-bind-plan.py:717-755`、`src/sweep.js:69-73`、`src/app.js:636`。
- 现象：真实 `selectAddrRows(bindPlan, sysIds)` 对 `0x0e23 / 0x0e08 / 0x0b23 / 0x0e01` 全 0；仅 `0x0f4d` 4 行。
- 影响：真车和模拟都会落旧 tabB1 fallback，再因 `requestKey=null` fail-closed。
- 修复：统一 ARCH §3.2、生成器、消费者。推荐**以生产结构为准**：消费者从 `pairs/truth/requestKeys` 派生 runtime rows，不再读不存在的 `can/requestKey`；生成器不再只给 `0x0f4d` 特例拍平字段。
- 门禁：用真实 `data/bind-plan.json` 调用真实 `selectAddrRows()`，不是 fixture。

### P0-2 模拟模式被真车 R 级契约误伤

- 位置：`src/app.js:710-713`、`app.js:168-172`、`src/live-map.js:218-252`。
- 现象：`state.simMode` 只有开关/清理，没有与真车 live-map gate 的完整分叉；mock 没有原生上报，却走真实 requestKey/native-report fail-closed。
- 影响：所有模拟车型进任意模块都可能通讯失败。
- 修复：在 `enterSystem/probeAddressFor` 之前按 `simMode` 显式短路；模拟用 mock 自身拓扑/应答，标 `provable:'sim'`，不进真车 live-map gate；真车 gate 不动。
- 边界：不得用 `rx=tx+8` 等自创推导，不得伪造真车正响应。

### P0-3 243 行的 `symbolHitOnly/runtimeAnswerBacked` 是快照，不是 live 重算

- 位置：`tools/build-align431-rows.mjs:460-471`、`tools/audit-align431.mjs:135-140`、`tools/verify-align431-qa.mjs:180/183/400-415`。
- 现象：build 期按类别给 row 分配向量并写快照；audit/QA 只读 row 字段。
- 影响：字段改名或类别映射正确但生产消费者坏掉时仍全 A。
- 修复：audit/QA 必须在当前 HEAD 上**重跑**生产数据消费、向量 diff、失败分类，不能信 rows.json 快照。

### P0-4 新归档实车/模拟向量未纳管

- 位置：`tools/vectors/realcar-981-bcm-20261120.json`、`tools/vectors/sim-991-ic-20261120.json`、`docs/realcar/README.md`。
- 现象：`npm test`、`audit:align431`、`verify-align431-qa.mjs`、`verify-align431-injection.mjs` 都不消费这两份向量；`mustReplay` 只是 JSON 声明。
- 影响：每次修复后仍可能不回放失败现场。
- 修复：加入强制向量清单；无回放或回放 diff 非空则不能标 A。

### P1-1 覆盖定义是静态字段，不是真执行覆盖

- 位置：`tools/verify-align431-qa.mjs:155-175`。
- 现象：Q02/Q03 以 `provable && e0Coord` 判 sysId 覆盖，报 130/130、623/623；真实 runtime rows 只有 1/623。
- 修复：覆盖判据改为「当前生产数据调用真实消费者得到 >0 行且证据/向量真执行通过」。

### P1-2 部分 R 级文本与 grade/provable 冲突

- 位置：registry #19 等。
- 现象：grade=R/provable=runtime，但 detail 以 `provable: static` 开头。
- 修复：R 级条目不得被任何 row 当 static verified；文本与结构化字段必须一致。

### P1-3 旧五组 e2e 向量仍有自证闭环

- 位置：`e2e-flow.mjs:36-68`、`tools/align431-eval.mjs:255/273/283-323`。
- 现象：同一 JSON 既当 expected 又当 replay；`vectorAnswers()` 只从 replay 文本找一条非 NO DATA 就算有应答。
- 修复：expected 与 replay 分离；应答 token 必须来自 e2e 实际发出的帧 dump；失败现场向量必须有负向断言。

### P1-4 关键 QA gate 未进 `npm test`

- 位置：`package.json:10`。
- 现象：`verify-align431-qa.mjs`、`verify-align431-static-truth.mjs`、`verify-live-map-failclosed.mjs` 不在 test 链；只在注入脚本里被调用。
- 修复：纳入 test 链，退出码参与全链通过。

## 2. 一次性修复范围与顺序

### 阶段 A：修 schema 契约（P0）

目标：生产数据可被真实消费者读出 runtime rows。

工作包 A1：
- 修改 `docs/ARCH-全链路真实对齐-20261120.md` §3.2，统一为生产真实 schema：`cands / pairs / truth / requestKeys / blockOff / blockKeys / fourTuple`。
- 若保留单数兼容字段，只能作为兼容别名，不能作为唯一数据源。

工作包 A2：
- 重写/新增 `src/bind-plan-rows.js`：纯函数，把真实 bind-plan 条目转成 runtime rows。
- `src/sweep.js:selectAddrRows()` 和 `src/app.js:636` 改用该函数。
- 不新增协议帧、不猜 CAN、不把请求键低 16 位当 CAN。

工作包 A3：
- `tools/export-bind-plan.py` 删除仅 `0x0f4d` 拍平的特殊待遇，或让所有条目都通过同一转换规则生成兼容字段；禁止一条特例掩盖全量断接。

- `0x0e08 / 0x0b08 / 0x1408 / 0x0623` 用真实数据 >0 行；
- 123/623 等无请求键 sysId 若无 runtime row，必须有 E0「无此路径/不需要进模块」证据，不得静默跳过。

### 阶段 B：模拟模式隔离（P0）

- `src/app.js:enterSystem/probeAddressFor` 在真车 gate 之前加 `state.simMode` 分叉；

- 真车 fail-closed 注入仍 100% 红。

### 阶段 C：消除静态冒充 R 级上报（P1）

- `src/app.js:147/737` 当应答无真实 frameId 时不得用 `row.rx/p.rx` 兜底；应返回 `uxth:0` 或 fail-closed。
- `src/live-map.js:reportNative()` 只接受真实 native report；静态行只能作候选，不能当上报。
- 注入：有 body 但无 frameId 的应答必须翻红。

### 阶段 D：门禁从快照改 live 重算（P0/P1）

工作包 D1：
- `tools/audit-align431.mjs` 在审计时对当前 `data/*` 重跑 `selectAddrRows()`、向量 diff、失败分类；不再信 `row.symbolHitOnly/runtimeAnswerBacked` 快照。
- `tools/verify-align431-qa.mjs` Q02/Q03/Q04/Q05/Q14 改为真执行覆盖判据。

工作包 D2：
- `tools/test-align431.mjs` 删除或降级合成 `can/requestKey` fixture；新增真实 bind-plan 消费者测试。
- 新增 `tools/verify-bindplan-runtime-contract.mjs`：专门验证生成器→消费者契约。

工作包 D3：
- 把 `verify-align431-qa.mjs`、`verify-align431-static-truth.mjs`、`verify-live-map-failclosed.mjs`、`verify-bindplan-runtime-contract.mjs` 接入 `package.json` test 链。

### 阶段 E：实车/模拟回放纳管（P0）

必须回放的最小向量集：

1. `realcar-981-bcm-20261120`：VIN/车型识别 + 后端电子设备失败现场；

- 未来新增字段必须同步更新 schema、生成器、消费者、门禁。
