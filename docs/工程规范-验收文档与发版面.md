# 工程规范：验收文档入库 与 发版面清洗

> 适用对象：本项目全体 agent（含后续接手者）。
> 生效基线：恢复 17 份根 `.md` 入库并落档本规范的修复提交。
> 本规范是硬约束，不是建议。违反会导致门禁空转、干净 clone 红、验收依据丢失。

## 0. 一句话原则

验收文档是**证据**，不是发布资产。发版面清洗只动发布物，不动证据。
任何造成「本机绿、clone 红」或「断言存在但不执行」的改动，一律视为回归。

## 1. 哪些文档必须入库

以下文档**必须**同时存在于 `git ls-files`、工作树与干净 clone：

- `CURRENT_SCOPE_DOCS`（7 份在册文档）：`AUDIT-20261112.md`、`B-TO-A-CLOSURE-20261112.md`、
  `GAP-INVENTORY-20261112.md`、`ACCEPTANCE-MATRIX.md`、`PRD-FULLALIGN-431-20261113.md`、
  `RE-GAPVERIFY-20261112.md`、`TAKEOVER.md`。
- 41 行基线（`GAP-INVENTORY-20261112.md` §2 `:41–:81`）所在文档。
- 审计证据坐标（`evidence431`）引用的文件。
- `ARCHIVED_REPORTS` 中已入库的归档报告。

执行口径：

- 允许用 `git add -f` 把被 `.gitignore` 命中的文档显式入库。在册/归档文档与 `.gitignore`
  的历史政策冲突时，**以入库为准**。
- **禁止**用 `git rm --cached`、`git rm`、新增 `.gitignore` 规则等方式把这些文档踢出跟踪。
- `git ls-files --error-unmatch <file>` 必须成功；这是门禁 `U2_SCOPE_DOCS_TRACKED` 的硬断言。
  非 git 环境显式判红，不得静默降级。

历史事故（2026-11-18，commit `310f280`）：新增 18 行 `.gitignore` 并把 17 份根 `.md`
退出跟踪（其中 `HANDOFF.md` 重复两次）。后果：本机因文件仍在磁盘而 U2/audit 假绿、
干净 clone 全缺、禁用结案词扫描集从 18 份塌成 1 份（门禁实质空转）。本规范为防复发而立。

## 2. 「发版面清洗」的边界

- 清洗对象**仅限真正发布资产**：bundle、公开页面、安装包、README 等对外可见内容中的
  第三方工具字样与绝对路径。
- **不得删除验收依据**：任何 `.md` 报告、审计、交接稿、PRD、矩阵，不得以「发版面」为由
  删除或退出跟踪。
- 需要中性化时**只改措辞、保留文档**：把具体第三方工具名替换为「原厂诊断仪」「参考设备」，
  把绝对路径替换为相对路径；文件内容与结构保留。
- 判断标准：改完后，禁用结案词扫描集份数不得下降、在册/归档文档 tracked 检查不得变红。

## 3. 干净 clone 是唯一验收现场

- 任何「完成 / 收口 / 全绿」的结论，必须在**干净 clone** 上复现：
  - `npm ci`
  - `npm test`
  - `npm run audit:align431`
- **本机绿而 clone 红等于没有绿**。本机未入库的临时文件让门禁通过属于假绿，与门禁空转同级。
- 跨机器对照以审计的 `sha256` 指纹为准：同一提交在本机与 clone 必须逐字符相同、
  连续两次运行逐字符相同。

## 4. 门禁断言不得放宽

- 已有断言（断言名、扫描集下限、在册文档 tracked 检查、分区/互斥检查、行为断言合计等）
  **只允许收紧，不允许删除或放宽**。
- 不得为了让红变绿而：删除断言、降低下限、扩大白名单，或把 gate 从「真执行」降级为
  「文件存在 + 文本含断言名」的假检查。
- 扫描集下限：入库根 `.md` 数不得小于 18（README + 17 份；出处：冻结基线 `965883d` 的
  `git ls-tree -r --name-only 965883d | grep '\.md$'`，计 18 行）。实现见
  `tools/verify-forbidden-words.mjs` 的 `FORBIDDEN_WORDS_SCANSET_MIN`。
- 未来若引入 `NO_ASSERTION_DELETED` 一类的断言完整性检查，同样不得删除或放宽。
- 新增门禁必须**真执行**（退出码 0 + stdout 命中断言名），并接入 `npm test` 与审计。

## 5. WIP ≠ HEAD

- 新增 gate 依赖的文件（工具脚本、数据、文档）**必须提交**；只在工作区存在不算落地。
- 宣称收口前 `git status` 必须干净（无未提交、无未跟踪）。
- 不要把「本机有、HEAD 没有」当成已交付 —— 干净 clone 不会带上这些文件。

## 6. 由工具生成的配置变更也要提交

- `npx cap sync` / `npx cap copy` 等生成的插件清单与原生工程配置（如
  `ios/App/App/capacitor.config.json`、`android/app/capacitor.build.gradle`、
  `android/capacitor.settings.gradle` 等）必须提交。
- 不能把这些变更留在工作区就结束任务 —— 否则 clone 上插件不完整，真机行为与本机不一致。
- 本条为规范记录；本次修复不改动任何此类文件。
