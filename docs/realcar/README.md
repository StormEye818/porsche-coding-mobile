# 实车 / 模拟应答回放样本（2026-11-20）

## 目的

这些文件不是用来「证明修复已通过」，而是用来**复现失败现场**。每次涉及 VIN 识别、车型分流、bind-plan 消费、候选解析、请求键绑定、会话或进模块帧序的修复后，验收都必须回放这些样本，确认：

1. 已观测帧的行为没有回退；
2. 已知失败形态没有再次出现；
3. 没有伪造样本里不存在的正响应。

## 观测到的共同失败

两份日志都出现：

```text
请求键缺失 → fail-closed（绑定入参必须是请求键）
候选全部无应答（来源 bind-plan），通讯失败
```

根因不是 431 E0 做法错，而是：

- 生成器写 `cands/pairs/requestKeys` 复数结构；
- 部分运行时读 `can/requestKey` 单数结构；
- `selectAddrRows()` 对真实 bind-plan 返回 0 行；
- 运行时落到旧 `ecu-addresses.json` tabB1 共享候选；
- 这些 fallback 候选被显式置 `requestKey:null`；
- 最后触发真车 live-map 的 fail-closed。

## 使用纪律

- 这些样本只能证明**观察到了什么**，不能证明样本里没出现的帧是成功的。
- 981 实车样本里，程序在发 `22 14 09` 之前就失败，因此没有 `0x070D/0x0777` 的正响应向量；任何回放都不得伪造它。
- 991 模拟样本只观测到 VIN/车型识别帧，不能拿它证明 IC 模拟进模块成功。
- 每次修复后的验收必须同时看：
  - 243/243 审计；
  - QA gate；
  - 本目录中的实车/模拟回放样本；
  - 注入反例仍可转红。

## 必要的后续门禁（本次未实现，因用户要求先不动手）

需新增真实数据而不是 fixture 的断言：

1. `selectAddrRows(realBindPlan,['0x0e23'])` 必须非空，且含 `0x070D/0x0777`；
2. `selectAddrRows(realBindPlan,['0x0e08'])` 必须非空，且请求键非空；
3. 模拟模式不得出现「请求键缺失 → fail-closed」；
4. 真车模式下，去掉原生上报或去掉请求键仍必须 fail-closed；
5. 回放上述两份向量时，观测帧必须与样本一致，且不得凭空新增样本中不存在的成功应答。
