## 0. 结论速览（先给判断）

1. **本代真值 CAN 对是静态数据，且就在 431 包里**：`PORSCHE_SYS_DATA.BIN` 的 comm `cat=0x10` 记录，
   `A`(tx)/`C`(rx) 为 SJA1000 风格 11-bit ID 左移 5 位打包（`tx=A>>5`，`rx=C>>5`）。
   导出见 `data/sysdata-comm.json` 的 `subs[].raw` 与 `byGeneration`，真值表见 `data/comm-addr-table.json`。
   → `data/bind-plan.json` 对 `gen<0x14` 不采此表（rule 明写"gen≥0x14 另把 SYS_DATA comm cat=0x10 …作为首选候选"），
     是本代真值 CAN 未进 bind-plan 的**直接原因**（见 E-10）。
2. **rx 不是一律 +8，且可全静态派生**：按代规则 `+0x6A`(gen 0x0B–0x16 主)、`+0x100`(gen 0x04–0x06)、
   `+0x10/+0x20`(gen 0x03)、`+8`(稀疏，含 0x0e01)、`rx<tx` 回绕(老代少数)。全部来自 `cat=0x10` 记录的 C 字段，
   无需车上实测即可得（见 E-11/E-12）。
3. **请求键与 CAN 是两个键空间，桥在链路绑定而非请求层**：DRIVELINKS 行 `A=flags<<16|internal`（请求键 `0x0030xxxx/0xFF60xxxx`），
   `PorscheSendCommandByID` 逐指令无查表/无 CAN 选择，目标由已绑定链路决定（见 E-06/E-07）。
   bind-plan 把 `v3key/v3cand` 低 16 位当 CAN 候选，是**把请求键空间错当 CAN 空间**（见 E-18）。
4. **431 不靠"全段枚举 0x700–0x7FF"找地址**：进模块=按变体选行（静态）→ 逐候选发 **1 帧** `22 14 09` 探针 →
   `send(0x10000359, A, 2)` 绑定 → `uxth==1` 确认。每候选 0/1 帧。"一次全段短扫 200ms/地址"是我方 RE-DISCOVERY §5②
   的**设计**（D 级），不是已证的 431 行为（见 E-04/E-05/E-19）。
5. **模块身份串/变体来源是静态可证的**：`GetSubSysDataAddr`（FILE:0x15c18）名字注册表 + JOB.BIN 件号 memcmp（见 E-09）。
6. **可复核 quantified discrepancy（口径已收口）**：gen<0x14 有 **172** 个 sysId 的 `cat=0x10` 真值 tx 不在 bind-plan cands；
   本 sysId 真值配对 **302** 对里 **281** 对 `rx≠tx+8`。与工单"172"一致。
   **307 与 281 不是同一判据**：307=此前"全表任意 tx 同值冲突"口径，281=本 sysId 真值配对 rx≠+8 口径，禁止混写（见 §F）。
   此前误报的 296 是大小写未归一化假多算，已废止。方向一致：**真值没进表 + +8 覆盖真值**（见 E-18 对照与 §F 复核命令）。
7. **【关键口径纠正】同一数值兼三类角色、语义分层，禁止互相替代（与 research-431-static-allmodels 交叉裁决一致）**：
   `0x0f4d` 是 `SWA2_BaseSys`(gen 0x0F) 的**合法 SYS_DATA sysId**（u32=0x0f4d 全文件仅 1 处 @0x35ee0，嵌在 `0x35EBC`
   这条 cat=0x10 记录尾部），**同时**是 DRIVELINKS 目录键 + 直连**请求键** `0x003006CC–0x003006CF`（低 16 位 `0x06CC–0x06CF`）
   ——三合一于同一数值，CAN 真值 `0x74E/0x7B8` 静态可证。
   `0x0e5f/0x0e60` 是**另一名字** `BV_ContrUnitLaneChangAssis2UDS_BaseSys`(gen 0x0E) 的 sysId（异名同功能），

   → **进模块查 live map 用请求键 `0x06CC–0x06CF`；身份裁决用名字串(SWA2_BaseSys / BV_*)+件号，不按 sysId 数值单一判断**（见 E-14）。
8. **DME 身份 sysId 全集 = `0x0b01/0x0c01/0x0e01/0x0f01`**；`0x0b23` 是 **BCM_hinten**（车身后部控制器），

9. **请求键→CAN 映射包内"三次负扫描 0 命中"，静态表不可导出该绑定**（RE-DISCOVERY §6）：紧凑地址表/请求键与 CAN 同记录/

   → **生成器输出每条必标 `provable: static|runtime`**；候选由 **431 静态行选取**（addrBlock 行/blockKey/变体匹配），
   "哪个候选是活地址"=R 级原生发现上报；**本地若拿不到原生上报则 fail-closed，不得静态写死 CAN，不得把 D 级全段枚举当 431 A 级做法**（见 E-20）。
10. **【实现禁令·对齐口径】不得把自创"连接期全段枚举 0x700–0x7FF/200ms 每地址"当 431 对齐证据**——那是 D 级我方设计，
   431 包内无全段扫描实现，进模块实为 0/1 帧探针（E-01）。**连接期 live map 若只能由原生上报（R 级），必须 fail-closed
   并保留 R 级标注：不能静态写死 CAN、不能标 A**（"谁应答/哪个候选活"以 431 整体可用性作机制证据，具体地址仍需车上实测，

## B. 请求键→CAN live map 的数据结构与建立

### E-06 两个键空间的分界（S）
- **做法**：
  - 请求键空间：`0x0030xxxx` / `0xFF60xxxx`（`flags<<16|internal`，flag `0x0030`/`0xff60`），
    作为 `send(0x10000359, A, 2)` 的 A 入参；DRIVELINKS addrBlock 行 A 字段（E-02）。
  - CAN 空间：11-bit `0x000–0x7FF`（诊断段 `0x700–0x7FF`），存于 `PORSCHE_SYS_DATA.BIN` comm `cat=0x10` 记录 A/C 字段（E-10）。
  - routing internal 空间：`0x01CB`/`0x00BC`/`0x02F9` 等（SYS_DATA 16B 行 f1），my方离线 join 键，非请求键（RE-ICADDR §2）。
- **原始路径**：`…/PORSCHE_DRIVELINKS.BIN`、`…/PORSCHE_SYS_DATA.BIN`
- **实现应做**：bind-plan 区分 `bindKey(请求键)` / `can(tx,rx)` / `routingInternal` 三列，禁止互相直取低 16 位。
- **反例**：`bind-plan rule` 写"v3直连键(bindKey低16位=CAN)"、`v3候选(rx→tx=rx-8)`——gen≥0x0E 全走此路，
  把请求键当 CAN（E-18 实算）。

### E-07 live map 建立时序（S 机制 / R 真值）
- **做法**：连接/进模块阶段：装载体 `GetData @FILE:0x160fc`（开 `PORSCHE_SYS_DATA.BIN`/`PORSCHE_SERVICE.GAG`）→
  候选数组（`Xml_GetSpecArray @0x18348` + addrBlock 行序）→ 身份登记 `GetSubSysDataAddr @0x15c18`
  （名字注册表 SearchID 命中 → 写 TOKEN+`0x604/0x608..0x638`）→ 发现循环（E-01）→ 绑定回调
  （`TOKEN[0x361800|0x3617FC]`，等价于 SetAddress/FilterId）。绑定后请求键→CAN 的关联才在链路层成立。
- **原始路径/偏移**：`GetData FILE:0x160fc`、`Xml_GetSpecArray FILE:0x18348`、`GetSubSysDataAddr FILE:0x15c18`、
  `DriveLinksMode_1001 LINK:0x18f00`、`SetAddress libCOMM_ABSTRACT_LAYER.so:0x37cfc`、
  `UpdateCanFilterId libPORSCHE_COMM.so:0x12238`。
- **可复核命令**：`grep -n "GetData\|GetSpecArray\|GetSubSysDataAddr" HANDOFF.md`（收官段 3616-3622 有逐链转写）。
- **实现应做**：runtime 先建 live map（请求键→已应答 CAN），进模块按请求键查表 0/1 帧确认；不信任缓存，每次回帧校验 ID。
- **反例**：本项目只在 `cands` 为空时 `ensureLiveMap`（工单已知败因）——伪候选（请求键低16）堵住兜底，live map 永不建立。

### E-08 模块身份串 → 变体的写回（S）
- **做法**：`GetSubSysDataAddr @FILE:0x15c18`（1188B）记录流 `[…u16 X][u32 p][u32 A..G]`（26/34B），

- **原始路径**：`…/libPORSCHE_FILE.so`、`…/libPORSCHE_ACTF.so`、`…/decoded/JOB.BIN`（≈0xbc21）、
  `…/decoded/GAG_*.GAG.bin` / `GAG_DSTREAM_CN.GAG.bin`。

- **反例**：`src/probe.js` 早期把 NRC 当"存活候选"并把 `7F2212` 记成识别串进模块（RE-ICADDR §5 已修）。

## D. 五个代表性 sysId 逐项证据（S）

> 统一复核法：在 `PORSCHE_SYS_DATA.BIN` 的 `commOff` 读 `[u32 A][u32 C]` → `tx=A>>5`、`rx=C>>5`、
> `delta=(C-A)>>5`；模块名从 `sysDataOff` 后 ASCII 串读出。bind-plan 现候选列对照见 E-18。

### E-13 sysId `0x0e23` — BCM_hinten（gen 0x0E）
- **原始坐标**：`PORSCHE_SYS_DATA.BIN:0x1191B`（raw `0xE1A0 EEE0`，m=3）；`sysDataOff=0x11941`。
- **真值**：`tx=0x70D`、`rx=0x777`、`rx=tx+0x6A`；模块 `BCM_hinten_BaseSys` / 变体 `BCM_hinten_9x1_GT4`。
- **请求键**：DRIVELINKS v3 `blockKey=0x236d`，行 internal `0x04ff/0x06a7/0x06a8…`，`bindKey=0x003004FF/0x003006A7…`（请求键空间）。
- **bind-plan 现状**：cands=`0x06A7,0x06A8,0x074F,0x07A5..0x07B4`（v3key/低16），pairs 全 `+8` → **真值 0x70D 不在表**。
- **实现应做**：以 cat=0x10 `0x70D/0x777` 为首选候选；请求键只作绑定入参。
- **反例**：`0x06A7→0x06AF(+8)` 这条 bind-plan pair，tx/rx 都不是本模块真值。

### E-14 `0x0f4d` ——【同一数值三合一 / 异名同功能 的典型反例】
> 与 research-431-static-allmodels 交叉裁决一致（原始字节双方各自复核通过）。**修正此前绝对化措辞**：
> 不再写"`0x0f4d` 不是 sysId"——它**本身是** `SWA2_BaseSys` 的合法 SYS_DATA sysId；要区分的是**身份按名字串+件号，不按 sysId 数值单一判断**。
- **权威裁决（原始字节）**：`PORSCHE_SYS_DATA.BIN` 中 u32=`0x0f4d` 全文件**仅 1 处** @`0x35ee0`，嵌在 `0x35EBC` 这条
  cat=0x10 记录 `+0x24` 的 sysId 字段；该记录 A/C=`0xE9C0F700`→`0x74E/0x7B8`，其后名字串 `SWA2_BaseSys` / `SWA2_A2_1`。
  → `0x0f4d` = `SWA2_BaseSys`(gen 0x0F) 的 SYS_DATA sysId，**同时**是 DRIVELINKS 目录键(@0x278) + 直连请求键
  `0x003006CC–0x003006CF`（低 16 位 `0x06CC–0x06CF`）——**三合一于同一数值**。
- **异名同功能（BV_*）**：`…:0x1402F`（sysId 字段 `0x0e5f`，raw 同为 `0xE9C0F700`→`0x74E/0x7B8`）与
  `…:0x14197`（sysId 字段 `0x0e60`，raw `0x9A404640`→`0x4D2/0x232`），两者名字串均为 `BV_ContrUnitLaneChangAssis2UDS_BaseSys`
  （gen 0x0E）。`0x0e5f` 与 `0x0f4d` **共享同一 CAN raw 但名字不同**（SWA2 vs BV_*）；`0x0e60` 走另一 CAN 对。
- **分层结论（四层不混）**：
  | 层 | 取值 | 用途 |
  |---|---|---|
  | SYS_DATA sysId | `0x0f4d`(SWA2) / `0x0e5f`,`0x0e60`(BV_*) | 数据记录定位；**异名不可合并** |
  | 请求键（DRIVELINKS bindKey 低16） | `0x06CC–0x06CF` | **进模块查 live map / 绑定入参** |
  | CAN 真值（cat=0x10 A>>5/C>>5） | `0x74E/0x7B8`(+0x6A) | 静态可证的地址对 |
  | 身份裁决 | 名字串 `SWA2_BaseSys`/`BV_*` + 件号（JOB.BIN memcmp） | **不按 sysId 数值单一判断** |
- **bind-plan 现状**：cands=`0x06CC..0x06CF`（把请求键低16当 CAN），pairs `+8`（`0x06CC/0x06D4`…）→ **真值 0x74E 不在表**。
- **实现应做**：进模块查 live map 用请求键 `0x06CC–0x06CF`；身份裁决用名字串+件号；CAN 取 cat=0x10 `0x74E/0x7B8`。
  门禁三元组建议（与静态线一致）：`{sysId:'0x0f4d', requestKey:[0x06CC,0x06CF], moduleName:'SWA2_BaseSys', can:{tx:0x74E,rx:0x7B8}, provable:static}`，
  并把 `0x0e5f/0x0e60` 作独立字段 `altIdentitySysIds`（异名同功能，**勿称"身份 sysId"**以免误解为唯一键）。
- **反例**：①`0x06CC→0x06D4` 是请求键+8，不是 SWA2 的 CAN；②因 raw 相同把 `0x0f4d` 与 `0x0e5f` 当同一 sysId 合并；
  ③写"`0x0f4d` 不是 sysId"（字面错误——它是 SWA2 的合法 sysId）；④用 sysId 数值单一判断身份（应按名字串+件号）。

### E-20 生成器输出契约（响应 team-lead 静态证据线结论）
- **三次负扫描 0 命中，静态表不可导出"请求键→CAN"绑定**（RE-DISCOVERY §6，本轮复核）：
  | 假设 | 扫法 | 结果 |
  |---|---|---|
  | 包内有紧凑地址表 | 6 个已证 CAN 锚点 64B 窗口 ≥4 个 | **0 命中**（243MB/77 文件）|
  | 请求键与 CAN 写在同一条记录 | 4 个真请求键 `0x003005C4/0x003005BF/0x003004C1/0xFF60026B` ±64B 找 CAN | **0 命中**；请求键仅在 `PORSCHE_DRIVELINKS.BIN` 出现 53 次，`.so` 内 0 次 |
  | DRIVELINKS 行 id ↔ SYS_DATA routing internal 桥表 | 3 组锚点对 16B 内共现 | 仅 3 处随机共现，不构成表 |
- **强制输出契约**：bind-plan / comm-addr-table / 任何生成器的每条 CAN 结论**必标 `provable` 字段**：
  - `provable: static` —— 仅用于 cat=0x10 记录直接给出的 `tx/rx` 与 rx 派生规则（`A>>5`/`C>>5` 可离线复算）。
  - `provable: runtime` —— 用于"请求键→哪条 CAN 最终绑定/哪个候选是活地址"；此部分**不得在静态表里写死 CAN**。
    **候选由 431 静态行选取**（DRIVELINKS addrBlock 行 + blockKey + 变体匹配，E-02/E-07）；"哪个候选是活地址"由**原生发现
    上报（R 级）**产生。本地若拿不到原生上报则 **fail-closed**——保留 R 级标注、不静态写死 CAN、不标 A。
    **禁止把 D 级"连接期全段枚举 0x700–0x7FF/200ms"写成 431 A 级做法**（431 包内无全段扫描实现，见 E-05/E-19）。
  - 二者语义分开存列（identity sysId / request-key / CAN / provable 四维），禁止合并（见 E-14 的 `0x0f4d` vs `0x0e5f/0x0e60`）。
- **反例**：在 bind-plan 里给 `0x0f4d` 写死一条"身份→CAN"的静态绑定（既错身份、又错把 runtime 当 static）；
  或输出 CAN 结论却不标 provable，使 runtime 绑定被下游误当静态真值。

> `0X…`≠`0x…` 全不命中），已废止。
> **307 ≠ 281，不是同一判据，禁止混写**：`307` 是此前"全表任意 tx 同值冲突"口径（跨 sysId、按 CAN 值聚合的总量）；
